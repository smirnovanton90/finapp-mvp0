# FinApp — дизайн-гайд

Этот документ — источник правил для дальнейшей разработки интерфейса FinApp. Новые экраны, компоненты и состояния должны продолжать существующий визуальный язык, а не вводить новый дизайн без явной причины.

## 1. Обзор приложения

FinApp — персональный финансовый кабинет: учёт активов и обязательств, транзакций, целей, бюджетного и финансового планирования, категорий, контрагентов и отчётов.

Интерфейс должен помогать быстро считывать финансовую картину, но не выглядеть как сухая банковская таблица. Это тёмный, собранный и немного «премиальный» продукт: крупные суммы, понятные статусы, мягкий фиолетовый свет, лаконичные карточки и спокойные анимации.

Основной сценарий — широкая десктопная рабочая область с постоянной навигацией слева. Мобильная версия — самостоятельный touch-first интерфейс, а не сжатая копия десктопа.

## 2. Визуальный стиль и общий тон

- Базовый стиль — глубокий тёмный `dark fintech`, построенный на почти чёрном, графитово-фиолетовом и лиловом акценте.
- Поверхности плоские или слегка «стеклянные»: полупрозрачные заливки, тонкие светлые границы, умеренные тени и `backdrop-blur` — только там, где он подчёркивает плавающий слой.
- Для плавающих поверхностей приложения допустима прозрачность по образцу нижней mobile-навигации: полупрозрачный фон `sidebar` (`#191732` с прозрачностью около 55–70%), тонкая граница и `backdrop-blur-xl`. Применяйте этот приём точечно — для floating bar, popover, sheet или компактного overlay, когда содержимое под слоем должно оставаться визуально ощутимым.
- Фиолетовый — функциональный акцент: текущий раздел, основное действие, выделение, фокус. Он не должен заполнять большую часть экрана.
- Цвет статуса семантичен: зелёный — положительная динамика/доход, красный — расход/ошибка/опасность, оранжевый — предупреждение, розовый — специальный плановый или эмоционально выделенный сценарий.
- Интерфейс дружелюбный, уверенный и предметный. Формулировки короткие, без канцелярита и декоративного маркетингового тона.
- Иконки — тонкие контурные Lucide, обычно `stroke-width: 1.5`; не смешивать их с тяжёлыми залитыми иконками в одном контроле.

## 4. Шрифты и типографика

- Единственный UI-шрифт: `CodecProVariable`, fallback: `ui-sans-serif, system-ui, sans-serif`.
- Используйте веса variable font от `400` до `700`. Обычный текст — `400`; подписи и кнопки — `500`; заголовки и финансовые итоги — `500–600`; `700` допустим для главного CTA и редких сильных акцентов.
- Базовый межстрочный интервал — `1.125` для всех display/UI-размеров. Не применять разреженную журнальную типографику.
- Цифры и денежные суммы набирайте тем же CodecPro; выравнивайте числовые колонки вправо. Не подменяйте шрифт табличными цифрами другого семейства.

| Роль | Размер | Вес | Примечание |
| --- | ---: | ---: | --- |
| Микро-label / currency chip | 10–11 px | 500–600 | Допускается uppercase только для кодов валют |
| Второстепенная подпись | 12 px | 400–500 | Даты, пояснения, metadata |
| Основной UI-текст | 14 px | 400–500 | Формы, списки, подписи кнопок |
| Основной текст / поля | 16 px | 400–500 | Удобный размер на mobile |
| Section title | 20–24 px | 500–600 | 20 px для mobile, 24 px для desktop |
| Крупное значение / card total | 24 px | 500 | Финансовые показатели |
| Заголовок modal | 24–32 px | 500 | 32 px — только для больших desktop-модалок |

## 5. Layout rules: desktop

- Desktop начинается с `768px`. На нём навигация фиксирована слева, с внешним отступом `10px` от края viewport и скруглённым контейнером.
- Sidebar имеет ширину `300px` в раскрытом виде или `100px` в свёрнутом. Пункты навигации: высота `50px`, внешние отступы `10px`, скругление `9px`, иконка `30px`.
- На страницах с фильтрами панель фильтров располагается справа от sidebar и имеет ширину `400px`; навигация и фильтры могут образовывать единую поверхность `#191732`.
- Контент учитывает ширину sidebar/фильтров. Эталонная ширина центральной области: `max-width: 900px`; при доступной ширине контейнера от `1400px` — `max-width: 1350px`. Центрируйте её по горизонтали.
- Для обычных страниц сохраняйте вертикальный центр только когда это соответствует сценарию (например, компактный экран профиля/пустое состояние); рабочие разделы начинаются естественно сверху.
- Внутренний ритм — сетка 4px: преимущественно `8`, `10`, `12`, `16`, `20`, `24px`; большие разрывы — `32px`.
- Списки и таблицы должны оставаться плотными и сканируемыми: не превращайте строку данных в слишком высокую «карточку» без причины.

## 6. Компоненты, скругления и обводки

| Элемент | Правило |
| --- | --- |
| Базовый радиус | `10px` (`0.625rem`) |
| Карточки, modal, dropdown, sidebar | обычно `9–10px` |
| Малые элементы (option, input, checkbox) | `6–8px` |
| Pills / badges / progress | `9999px` |
| Главные круглые кнопки mobile | `50%` |
| Базовая карточка (desktop / shadcn Card) | фон поверхности, тонкая граница; стандартный компонент использует `border: 2px` с `border-color/70` |
| Мобильная контент-карточка | эталон `AssetCard`: `MODAL_BG`, `rounded-lg`, без бордера и без тени (см. §7) |
| Внутренние отступы карточки | как правило `24px`, в compact-элементах `12–16px` |
| Поле ввода | высота около `40px`, текст `14–16px`, спокойная граница/заливка, заметный accent focus |
| Primary button | скруглённая (`rounded-lg` или `rounded-full` по контексту), контрастный текст, accent/gradient фон |
| Secondary / glass button | прозрачный или полупрозрачный фиолетовый фон, без тяжёлой рамки |
| Overlay | `rgba(0,0,0,0.50–0.60)` |

Hover и focus должны быть спокойными: смена заливки/opacity, лёгкая тень или accent-ring. Для интерактивных изменений используйте 150–300 ms; для смены темы и крупных фоновых градиентов допустимо 700 ms. Учитывайте `prefers-reduced-motion`.

## 7. Особенности мобильной вёрстки

- Mobile — всё, что уже `767px` и меньше. Базовый фон всегда чёрный, независимо от выбранной темы; не переносите desktop-градиент целиком на экран телефона.
- Корневой экран живёт в `100dvh`, учитывает `safe-area-inset-*` и имеет отдельный скроллируемый контентный контейнер. Не рассчитывайте высоты через старый `100vh`.
- Горизонтальные padding контента — `16px`; снизу всегда оставляйте место под плавающую навигацию.
- Постоянный desktop-sidebar скрыт. Основная навигация — нижняя плавающая панель: отступ `12px` от краёв и safe area, `min-height: 64px`, `rounded-2xl`, полупрозрачный фон sidebar с `backdrop-blur-xl`, тонкая граница и мягкая тень.
- В панели доступны Dashboard, Planning, Assets и Transactions; центральная круглая кнопка `48×48px` использует `#7F5CFF` с прозрачностью, accent-тень и лёгкий scale при tap. Подписи пунктов — `10px`. Активный пункт — цвет accent `#7F5CFF`, без подъёма и без точки-индикатора.
- **Эталон мобильной подложки контента** — карточка актива на вкладке «Активы» (`AssetCard`): фон `MODAL_BG` / `#25243F`, скругление `rounded-lg` (`8px`), без бордера, без тени, `overflow-hidden`. Этот же стиль обязателен для информационных/навигационных блоков на дэшборде, странице актива и других mobile-экранах. Не подменяйте его `rounded-xl`, `border-white/10` или тяжёлой тенью. Исключения: нижняя плавающая навигация, bottom sheet (`#1C1B2E`), семантические алерты (например, просроченные операции) и glass/floating overlays из раздела 2.
- Не просто сжимайте desktop-таблицы. На mobile превращайте сложные наборы данных в вертикальные карточки/секции, раскрывающиеся списки, нижние шторки или полноэкранный flow.
- Фильтры показывайте отдельной выезжающей панелью, выборы и сложные действия — через overlay или bottom sheet.
- Bottom sheet имеет тёмную поверхность `#1C1B2E`, скруглённый верх, overlay `#000` 50%, жесты закрытия (тап вне, swipe вниз, пороговый scroll) и короткую анимацию около `320ms`.
- Touch targets должны быть не меньше ~44px. Для действий применяйте визуальный отклик `active:scale-90` или мягкое изменение заливки, не только hover.
- На мобильных UI-элементах отключено выделение текста; в `input`, `textarea` и `contenteditable` выделение остаётся доступно. Caret и selection — accent (`#7F5CFF` / `#5544D1`).
- Для мобильной страницы актива допустим насыщенный локальный фиолетово-оранжевый gradient header; это исключение для hero/detail зоны, а не общий фон всех экранов.

## 8. Чего избегать

- Не использовать светлый фон, белые карточки и нейтрально-синий «корпоративный» стиль в тёмной части приложения.
- Не добавлять новые случайные оттенки фиолетового, серого или статуса, если есть токен из раздела 3.
- Не заливать всё ярким accent: он нужен для иерархии, а не декора.
- Не использовать крупные радиусы (`20–32px`) на обычных desktop-карточках и формах; это нарушает компактность системы. Исключения: floating nav и отдельные mobile sheet/pill элементы.
- Не делать толстые непрозрачные границы, агрессивные тени, неон, glassmorphism на каждом контейнере или чрезмерно сложные градиенты.
- Не смешивать разные шрифты, системный шрифт для цифр и несогласованные начертания.
- Не делать мелкий текст менее 12px для важных данных, не полагаться на цвет как единственный носитель статуса и не использовать красный/зелёный для нейтральных действий.
- Не переносить desktop-sidebar, многоколонные таблицы и hover-only сценарии на мобильный экран без мобильной альтернативы.
- Не добавлять длительные или отвлекающие анимации: финансовые данные должны ощущаться стабильными и надёжными.

## 9. Проверка перед сдачей нового интерфейса

- Экран использует существующие цвета, CodecPro и 4px spacing rhythm.
- На desktop проверены раскрытый и свёрнутый sidebar; на фильтруемых экранах — открытая и закрытая панель фильтров.
- На mobile проверены ширины 320–430px, safe areas, нижняя навигация, keyboard/input и отсутствие перекрытия последней строки контента.
- Мобильные контент-блоки используют эталон подложки `AssetCard` (`MODAL_BG`, `rounded-lg`, без бордера/тени), если это не floating/sheet/alert.
- Текст и суммы читаемы на фоне, интерактивные элементы имеют focus/tap feedback, а положительные/отрицательные статусы понятны не только по цвету.
